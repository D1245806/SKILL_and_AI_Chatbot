# Product Requirements Document (PRD)

## 1. 產品概述

本產品為一個基於 Google Gemini API 的 AI 聊天機器人，提供具備前後端分離架構的對話平台。使用者可透過網頁介面與 AI 進行多輪對話，系統支援多個獨立的聊天室（Session），並能持久化儲存對話歷史。

**產品名稱**：Gemini AI 聊天機器人  
**版本**：v1.0.0  
**技術棧**：HTML + FastAPI + SQLite + Google Gemini API

---

## 2. 目標使用者

| 使用者類型 | 描述 |
|-----------|------|
| 學生 | 需要 AI 輔助學習、解題、撰寫報告 |
| 開發者 | 需要程式碼建議、技術問答 |
| 一般使用者 | 日常問題諮詢、資訊查詢 |

---

## 3. 核心功能需求

### P0（必要功能）

| 功能 ID | 功能名稱 | 說明 |
|---------|---------|------|
| F-01 | 對話狀態管理 | 支援多聊天室（session），每個 session 維持獨立的上下文 |
| F-02 | 訊息系統 | 訊息結構包含 role（user/assistant）、content、timestamp |
| F-03 | 對話歷史管理 | 可顯示並切換過去的對話紀錄 |
| F-04 | AI 對話 | 整合 Gemini API 產生智慧回覆 |

### P1（重要功能）

| 功能 ID | 功能名稱 | 說明 |
|---------|---------|------|
| F-05 | 上傳圖片或文件 | 支援使用者上傳 PNG/JPG/PDF 作為對話內容 |
| F-06 | 回答控制 | 提供重新生成（Regenerate）功能 |
| F-07 | 記憶機制 | 儲存使用者偏好（如語言、回應風格），實現跨對話持續性 |

### P2（加值功能）

| 功能 ID | 功能名稱 | 說明 |
|---------|---------|------|
| F-08 | 工具整合 | 串接 Open-Meteo 天氣 API，使聊天機器人能回應天氣查詢 |

---

## 4. 非功能需求

| 類別 | 需求 |
|------|------|
| **效能** | API 回應時間 < 3 秒（不含 AI 生成時間） |
| **可用性** | 支援 Chrome、Firefox、Edge 最新版本 |
| **安全性** | API Key 不得暴露於前端；使用 `.env` 管理機密 |
| **可維護性** | 程式碼需附有中文註解 |

---

## 5. 使用情境（User Stories）

1. **身為使用者**，我想要建立新的聊天室，以便針對不同主題分開對話
2. **身為使用者**，我想要切換歷史聊天室，以便回顧過去的對話內容
3. **身為使用者**，我想要上傳圖片讓 AI 分析，以便獲得圖片相關的說明
4. **身為使用者**，我想要重新生成 AI 的回答，以便獲得不同角度的回覆
5. **身為使用者**，我想要查詢天氣資訊，以便透過聊天機器人了解當地天氣

---

## 6. 驗收標準

- [ ] 可建立、切換、刪除多個聊天室
- [ ] 訊息正確儲存於 SQLite，重啟後歷史不消失
- [ ] 上傳圖片後 AI 能正確描述圖片內容
- [ ] Regenerate 功能能刪除舊回答並重新生成
- [ ] 輸入「台北天氣」時，系統能呼叫 Open-Meteo API 回傳實際天氣

---

## 7. 不在範圍內（Out of Scope）

- 使用者帳號系統（登入/註冊）
- 多語言 UI 切換
- 行動裝置 App
- 即時多人協作對話
